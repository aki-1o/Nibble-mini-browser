Nibble

A tiny Electron browser with a built-in API console, for testing Account Aggregator consent journeys.

What not to open

Read this first

Open AA consent journeys and your own localhost dev server. Nothing else.

Not your email, not your bank, not a link someone sent you, not a login page for anything you care about.

Every tab here is created with webSecurity: false. That is deliberate — it is what lets a journey's cross-origin API calls work without CORS headers, which is the entire point of the tool. But it also removes the same-origin policy, the boundary that normally stops one site from reading another.

With it off, script on any page loaded here can fetch any other origin using your cookies and read the response back. A hostile page could request your webmail or your bank's account page and read the HTML. Real Chrome makes that impossible; this does not.

Three settings make it worse

Setting What it costs you
allowRunningInsecureContent An HTTPS page may pull in HTTP scripts, so anyone on your network can inject code into a page that looks secure.
contextIsolation: false Page script shares a world with the preload script, which is far closer to code execution on your machine than a normal tab.
nodeIntegrationInSubFrames The same applies inside nested iframes, not just the top document.

All tabs also share one session and cookie jar, so a session created in one tab is reachable from every other tab.

So do not open

  • anything you are signed in to that matters — email, banking, cloud consoles, source hosting, internal admin tools;
  • links from outside your own testing — chat, email, search results;
  • unfamiliar shortener links. The journey flow legitimately uses urlshortner.uat.ignosis.ai, and that is fine because you know where it came from.

Two things that limit the damage. Nibble runs in its own Electron session, so your system Chrome's cookies and logins are not reachable from here — the exposure is limited to what you do inside Nibble. And the API key in the console is stored in localStorage in plaintext, so use a test key, never a production one.

HAR exports are sensitive. They contain full request and response bodies, including ecreq payloads, tokens and cookies, with no redaction. They are written locally and never uploaded, but treat the files as secrets.

Pinning Nibble to the taskbar

Do not pin the window that npm start opens. That process is Electron's generic runner with this project passed as an argument. Pinning captures the executable but not the argument, so relaunching it opens Electron's welcome screen instead of Nibble. If you have already pinned it, right-click the icon and choose Unpin from taskbar.

To get a pinnable app, build one:

npm run dist   # installer + portable, a few minutes
npm run pack   # just release\win-unpacked\, much quicker

Option 1 — install it (best if you mostly use the tool)

Run release\Nibble Setup 1.0.0.exe. It lets you choose the install folder and adds Start-menu and desktop shortcuts, so Nibble behaves like any other installed app. Pin it from the Start menu.

The catch: after changing code you must rebuild and re-run the installer for the change to appear.

Option 2 — pin the unpacked build (best if you are still editing)

Pin release\win-unpacked\Nibble.exe directly. That path carries no version number, so npm run pack overwrites the same executable in place and your pinned shortcut keeps working. Close the app before rebuilding, or electron-builder cannot overwrite the running file.

Option 3 — pin the portable build

release\Nibble 1.0.0.exe runs from wherever it sits and installs nothing. It pins fine, but the filename carries the version, so bumping to 1.0.1 breaks the pin.

Where your data lives. The AA list is in %APPDATA%\Nibble\nibble.db, not next to the executable, so it survives reinstalls and upgrades and is shared by the installed and unpacked copies. Running unpackaged via npm start is the exception: it uses %APPDATA%\Electron instead, so it has its own list.

SmartScreen. The build is not code-signed, so Windows warns on first run: More info → Run anyway. Signing needs a certificate and nothing in the app requires it.
